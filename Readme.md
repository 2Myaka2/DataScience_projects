Этап 3: создание выборок
Разделите датафрейм с заказами df_orders на выборки. В этом проекте вам предстоит  использовать «классическое» разделение на три выборки: обучающую, валидационную и тестовую.
При этом для решения задачи нельзя использовать обычный train_test_split. Дело в том, что заказы одного и того же клиента часто похожи: один и тот же адрес, специфика товаров и привычки. Если разные заказы одного человека попадут и в обучение, и в тест, модель распознает знакомого клиента и выдаст правильный ответ по памяти, не анализируя значения признаков. Произойдёт типичная утечка данных.
Ваша цель — построить систему, которая сможет предсказывать риски для абсолютно новых клиентов, которых компания ещё не видела. Чтобы валидация в таких условиях была честной, необходимо использовать специальный метод — GroupShuffleSplit. Он делит данные так, чтобы группы (в случае этих данных — клиенты) не пересекались.
В сворачиваемом блоке ниже и тетрадке проекта можно найти код, который демонстрирует, как работать с GroupShuffleSplit:
Ниже приведён пример того, как отделить часть данных для обучения, используя customer_id как ключ для группировки.

from sklearn.model_selection import GroupShuffleSplit

# 1. Выбираем колонку, по которой будем группировать (наши "группы")
groups = df_orders['customer_id']

# 2. Инициализируем сплиттер (например, отделим 20% клиентов для теста)
gss = GroupShuffleSplit(n_splits=1, test_size=0.2, random_state=RANDOM_STATE)

# 3. Получаем индексы для разделения
# Метод split возвращает генератор, поэтому используем next()
train_idx, test_idx = next(gss.split(df_orders, groups=groups))

# 4. Формируем выборки
df_train = df_orders.iloc[train_idx]
df_test = df_orders.iloc[test_idx]

t-SNE — «прожорливый» алгоритм прожорливый, и на больших данных или слабых виртуальных машинах он может выполняться очень долго. Если вы работаете на сервере Практикума и сталкиваетесь с тем, что ячейка работает дольше 5 минут, а результата всё нет, попробуйте ряд возможных решений:

На первый взгляд, это кажется нелогичным: ведь номер кластера — это просто метка, у которой нет математического порядка. Почему тогда бустинг иногда работает лучше, если воспринимает его как число?
Работая с числами, модель работает с обычными числовыми порогами. Когда дерево видит число, оно ищет порог (например,

Работая с категориями, CatBoost включает сложную механику — Ordered Target Statistics. Модель вычисляет среднее значение целевой переменной для каждого кластера по отдельности.
Плюс подхода: это теоретически более точный способ работы с категориями.
