Разработать ML‑модель, прогнозирующую вероятность отмены бронирования. Она должна минимизировать финансовые потери сети отелей и по возможности повышать загрузку номеров. Её задача — предсказывать вероятность отмены брони по входным данным. Это позволит UrbanStay принимать обоснованные решения о повторном бронировании или сохранении брони.

Шаг 3: объединение данных об отзывах и брони. Соедините таблицу отзывов с таблицей бронирований. Руководствуйтесь правилом: для каждой даты бронирования в столбце booking_date нужно взять комментарий и оценку клиента по предыдущей ближайшей дате отзывов, указанной в столбце review_date. Это позволит связать обратную связь клиента с конкретным периодом проживания, что критически важно для анализа удовлетворённости гостей.
Разберём правило на примере:
Предположим, в таблице бронирований есть строка, для которой указана дата 01.02.25 в столбце booking_date.
У этого клиента есть две прошлые брони. Он решил поделиться опытом проживания в отеле и оставил свои комментарии и оценки для обоих визитов.
Эта информация содержится в таблице отзывов. Первый визит клиент описал и оценил 01.02.24, а второй — 01.12.24. Эти даты указаны в столбце review_date.
Ближайшая к дате в booking_date дата в review_date — это 01.12.24, а не 01.02.24. Значит, комментарий и отзыв, оставленные 01.12.24, надо подтянуть к строке, где в booking_date указано 01.02.25.
Шаг 4: Feature Engineering.
Создайте не менее трёх признаков на основе данных о брони. Например, вы можете создать признак сезонность, опираясь на даты планируемого заезда. Этот признак позволит вам различать визиты гостей в высокий и в низкий сезоны, анализируя рыночный спрос. Другой пример — признак лояльность клиента, его можно рассчитать на основе количества предыдущих бронирований.
Создайте новые признаки на основе текстов отзывов. Используйте один из изученных вами инструментов векторизации (например, TfidfVectorizer ).

## Этап 2: моделирование
Цель этапа: подобрать оптимальную модель машинного обучения, стараясь максимизировать метрику Incremental Revenue.
Шаг 1: выбор модели. Выберите и обучите не менее двух моделей из списка:
Random Forest;
CatBoost;
LightGBM;
XGBoost;
любую другую на ваш выбор.
При поиске лучшей модели:
Разделите данные на три выборки:
обучающую — для обучения моделей (60% данных);
калибровочную — для проведения калибровки модели (20% данных);
тестовую — для финальной оценки качества выбранной модели (20% данных).
Проведите кросс-валидацию, используйте три фолда. Размер выборки для валидации — 2000.
Оптимизируйте гиперпараметры с помощью Optuna. Количество гиперпараметров — не менее трёх. Ключевая метрика для оптимизации — Incremental Revenue.
Шаг 2: калибровка лучшей модели. Выбрав модель, откалибруйте её на полной тренировочной выборке, чтобы повысить обобщающую способность и адаптировать предсказания под бизнес-задачи.
Шаг 3: оптимальный порог. Используя откалиброванную модель и калибровочную выборку, найдите порог классификации, при котором достигается максимальный Incremental Revenue.
Шаг 4: стабильность метрик. Сравните матрицы ошибок и IR на калибровочной и тестовой выборках.
Шаг 5: анализ важности признаков. Оцените важность признаков с помощью любого подходящего инструмента:
feature_importances;
SHAP;
встроенной в модель собственной функции оценки важности.
Сделайте выводы о влиянии признаков на целевую переменную.
